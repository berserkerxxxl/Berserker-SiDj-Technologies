В форме была выбрана операция `status`; развёртывание не запускалось и активация webhook не выполнялась. Прежняя диагностика не различала Cloudflare API и адрес Worker, поэтому источник 403 пока не установлен. Добавлено безопасное различение сервиса и вывод только числовых API-кодов; операция по умолчанию изменена на `deploy`. Подтверждение Workers Free отмечено владельцем в форме запуска; тариф через API не проверялся.

30.10.2026 в 21:40 МСК запуск `deploy` №41108626920 опубликовал Worker и секреты. Повторный запуск также подтвердил эти шаги. Оба завершились с ошибкой только на проверке публичного адреса. Контрольное сравнение установило причину: стандартный `Python-urllib` получает HTTP 403 с телом `error code: 1010`, а явно идентифицированный `B/S-tech-SiDj-operations/1.0` — HTTP 200 с ответом Worker. Служебный HTTP-клиент исправлен: он открыто указывает имя проекта и URL исходников, без имитации браузера или отключения защиты Cloudflare. Причина не была задержкой публикации.

На опубликованном Worker проверены шесть настоящих HTTP-запросов: `/` и `/setup` — 200; GET `/activate` и `/admin/activate` — 405; POST `/admin/activate` без служебного ключа и POST `/telegram` без секрета — 403. Панель возвращает CSP. Это ещё не подтверждает положительную авторизацию и доставку Telegram; их проверяет следующий `activate` и реальные действия владельца.
