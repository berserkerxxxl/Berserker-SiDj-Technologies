# Проверка B/S Reserve 0.1.0-alpha.5

Билд: **20261029.3**. Дата: **29 октября 2026 года**.

Проверки выполнялись на вымышленных данных. Доступ к аккаунту пользователя и его содержимому не использовался.

## Интерфейс

Базовый сценарий интерфейса выполнен для альфа.1; в альфа.2 дополнительно проверяются новые платформенные подписи, ограничения автоматизации и страница скачивания.

В headless Chromium на Linux выполнен сценарий:

1. Первый запуск с пустым каталогом.
2. Импорт трёх вымышленных источников: один разговор, две версии, одна запись памяти.
3. Поиск по тексту и открытие переписки.
4. Сохранение отдельной инструкции.
5. Проверка SHA-256 через локальный интерфейс.
6. Создание зашифрованного репозитория и снимка.
7. Получение списка, полное чтение и проверенное восстановление.
8. Формирование ZIP для переноса и открытие автономного HTML без сервера.
9. Поиск и чтение в автономном архиве.
10. Проверка ширины интерфейса на 1440 и 390 пикселях; горизонтального переполнения нет.

Ошибок JavaScript в этом сценарии не обнаружено. Внешних сетевых запросов от интерфейса B/S Reserve не обнаружено. Скриншоты использовались только для внутренней визуальной проверки и не включены в поставку.

## Компоненты

- thekester: закреплён коммит 13568bf75688de74a5af563b20d5ccd28f4ad532.
- D1DX: закреплён коммит 7d316cb064786207759b8d692abe4506dab459e0.
- restic 0.19.1 для Windows x64, macOS Intel/Apple Silicon и Linux x64/ARM64: контрольные суммы архивов сверены с опубликованными SHA256SUMS и digest GitHub release; в каждой поставке включён неизменённый бинарный файл своей платформы. SHA-256 вшит в приложение и проверяется перед первым использованием.
- Проверен синтаксис **24 JavaScript-файлов** модифицированных коллекторов и наличие файлов из трёх манифестов.
- Защитные обёртки в тесте разрешили GET и отвергли DELETE, PATCH, PUT и POST.
- Выполнен go vet на Linux x64; workflow проверяет остальные целевые ОС нативно.
- Пять платформенных бинарных файлов собираются из общего исходного кода Go без cgo и внешнего интерпретатора.

## Что ещё не проверено

**Интерактивное открытие .app через Finder/Gatekeeper, выполнение расписания на пользовательском ПК и работа расширений в живом аккаунте ChatGPT ещё требуют проверки.**

Для выпуска добавлен обязательный workflow «Test and Package B/S Reserve»: ubuntu-24.04 (x64), ubuntu-24.04-arm, macos-15-intel, macos-15 (Apple Silicon), windows-2025 (x64). Он запускает Go-тесты и go vet, затем готовую программу с реальным restic: пустой архив, защита API, тестовый импорт и дедупликация, запись инструкции, сверка, шифрование, полная проверка, восстановление и пакет переноса. Путь теста содержит пробелы и кириллицу. На Linux x64 также включается -race; на Windows тест проверяет шифрование/разблокирование DPAPI и отказ при подмене синтетического ключа. Публикация архивов блокируется, если любая платформа не прошла проверку. Ссылка на конкретный запуск добавляется к протоколу на странице проекта после сборки.

Эти проверки не заменяют испытание на целевом пользовательском компьютере и не требуют доступа к ChatGPT. Хранение ключа и встроенное расписание macOS/Linux не реализованы в этой альфе.

Скорость и полнота обработки многолетнего реального аккаунта, текущий формат улучшенной памяти и большие выгрузки около пределов прототипа требуют проверки на фактических источниках. Первый выпуск не объявляется полным резервированием аккаунта.

## Регрессии альфа.3

Проверяются вывод в выбранную папку при недоступном Outbox, отсутствие временных ZIP, запрет вывода внутри Vault, целостность источника после отказа, защищённое скачивание пакета вне Outbox и сохранение выбранного пути. Диалог выбора папки проверен через API с имитацией выбора и отмены; запрос без токена отклоняется.

Время Windows проверяется на диапазон 00:00–23:59. Дополнительный нативный тест Windows при BS_TEST_SCHEDULER=1 создаёт временную задачу, читает её XML, меняет время той же задачи и удаляет её. Интерактивное открытие и выбор системной папки требуют проверки на пользовательском ПК.

## Проверка диалога альфа.4

Дополнительный тест Windows с BS_TEST_FOLDER_DIALOG=1 открывает реальный FolderBrowserDialog, находит его окно через Win32, проверяет видимость владельца и WS_EX_TOPMOST у владельца и диалога, затем отменяет процесс и проверяет закрытие окна. При отсутствии интерактивного рабочего стола тест явно пропускается. Проверка API также подтверждает снятие блокировки после отмены HTTP-запроса.

## Вложения и имена альфа.5

Четыре новые общие проверки на вымышленных данных покрывают: применение карты к старому каталогу без повторного импорта и без изменения каталога; область действия карты в подпапке; неизвестные и отсутствующие файлы; API скачивания с исходным именем и неизменными байтами; связь по идентификатору сообщения и по пути с ID чата; отсутствие привязки по одному имени; совпадающие читаемые имена у разных файлов; безопасный манифест и ZIP; длинные имена с сохранением расширения на разных файловых системах.

Программа не выводит содержимое файла из имени и не воссоздаёт отсутствующие байты. Для проверки интерфейса используются синтетические PNG и PDF, включая имя с кириллицей, пробелом, # и %. Приватная карта пользователя в код и тестовые файлы не включена.

Сценарий Chromium для альфа.5 пройден: отчёт «3 из 4» для синтетической карты с одним отсутствующим файлом; поиск по имени; скачивание PDF с точными байтами; раскрытие PNG в сообщении; отдельное вложение аудио по пути чата; распакованный file:// без сервера; имена с кириллицей, # и %; поиск несвязанного файла; ширина 390 пикселей. Ошибок JavaScript и внешних сетевых запросов не обнаружено.

## Нативная проверка выпуска на GitHub Actions

Публикация файлов выполняется только после успешных проверок всех пяти целей: Windows x64, macOS Intel и Apple Silicon, Linux x64 и ARM64. На каждой цели запускаются тесты Go, go vet и скомпилированная программа с полным циклом restic. На Linux x64 включён детектор гонок; на Windows проверены DPAPI и создание/изменение временной задачи с выбранным временем.

[Протокол сборки и тестов](https://github.com/berserkerxxxl/Berserker-SiDj-Technologies/actions/runs/40886618830). В Windows дополнительно проверяются видимость системного диалога, его положение поверх обычных окон и отмена; при отсутствии интерактивного рабочего стола пропуск явно указан в логе. Первый пользовательский запуск с браузером, Finder/Gatekeeper и реальный аккаунт ChatGPT требуют отдельной проверки.
